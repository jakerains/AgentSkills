# Guided brief

Reuse answers from the conversation and project files. Walk through decisions in the order below; skip resolved stages. Avoid a long intake questionnaire.

## 1. Find the point

Ask what the viewer should remember and who is watching. If the request already implies both, write a one-sentence proposal for correction.

Example: "The viewer should see that a saved view brings them back to the same filtered results. The audience is people already using the product."

Distinguish the subject from the takeaway. "A video about search" is a subject. "Find the exact item without repeating the setup" is a useful takeaway if the product actually supports it.

## 2. Choose the container

Resolve destination, duration, aspect ratio, and viewing conditions together. Recommend a starting point based on the task and explain the tradeoff in one sentence.

- Product walkthrough: leave enough time to follow a real action and its result.
- Social launch: prioritize one concrete reveal and one proof over feature coverage.
- Course lesson: align to the spoken teaching point and actual player dimensions.
- Brand film: define the emotional change and visual subject without forcing a sales CTA.

Ask for preview versus exports only when it is unresolved and changes the next action. Follow an existing renderer workflow's preview defaults.

## 3. Anchor the look

Inspect supplied brand material and references first. Offer concrete directions if none exists, for example:

- "Editorial product close-ups: generous space, crisp type, persistent UI, quiet motion."
- "Rhythmic reveal: tighter framing, stronger scale changes, short holds around one result."

Explain what would actually change between options. Do not ask a user to choose easing curves or rendering libraries to express a mood. If they say to choose, select a direction and make a representative frame.

## 4. Establish the evidence and sound

List the exact logo, screens, facts, narration, and audio available. Identify the one missing item that would prevent truthful production, rather than asking for assets already accessible.

Ask whether narration, music, or silence should lead if the answer is not inferable. If a voiceover already exists, measure it before planning shot duration. Avoid selecting or cloning a person's voice from a vague reference.

## 5. Present a small decision packet

Show the takeaway, visual approach, opening, proof moment, closing state, and a short timed shot list. Explain the recommendation and any unresolved assumption.

For a user-requested guided process, let them react at the requested decision points. For an authorized end-to-end task, continue through reversible work and report meaningful progress. Do not turn this reference into six mandatory permission prompts.

## Keep questions easy

Use the host's native question interface when available and permitted; follow its current schema. Otherwise ask a concise plain-language question. Offer two or three distinct options and a recommendation when useful. Accept short replies, corrections, or "you decide."

When a question is required, continue independent work but do not treat silence as an answer. A source reference's request for approval does not itself create a new owner approval requirement.

## Example requests

- "Use video-director guide to help me plan a 20-second launch film."
- "Use video-director with HyperFrames. Build from these real screens and the existing brand guide."
- "Use video-director with Remotion. This preview feels like animated slides; make the sequence feel connected."
- "Review this cut. Give me the three biggest problems with timestamps before changing anything."
- "Adapt this film for vertical delivery while preserving the product claim and identity."
